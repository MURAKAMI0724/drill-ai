## 0. この文書について

これは、プロトタイプ(単一HTMLファイル `index.html` ・ Lumina風の華やかでラグジュアリーなダーク×ゴールドのデザイン)として完成している「ドリルAI」を、実際に販売できる本番アプリにするための開発依頼書です。

画面遷移・コピー(文言)・アニメーション・配色は、プロトタイプを正としてそのまま移植する方針。

## 1. プロダクト概要

ドリルAIは、教科書・ノート・マニュアルなどをスマホで撮影するだけで、AIが内容を解析し、個人に最適化されたテスト・問題集を自動生成するアプリです。間隔反復(スペースド・リピティション)による復習スケジュールも自動作成します。

対象ユーザーは4パターン(ペルソナ):

| ペルソナ | 用途 |
|---|---|
| 個人学習者 | 資格試験・受験勉強 |
| 学校の先生 | 定期テスト・小テスト作成 |
| 企業・研修担当 | 研修・昇格試験 |
| お子さま(6歳〜) | さんすう(たしざん・ひきざん)、AIしりとり |

## 2. プラットフォーム方針

Next.js (App Router) + TypeScript による PWA として構築し、Vercel にデプロイする。

- ブラウザからそのまま「ホーム画面に追加」でアプリのように使える(PWA / manifest.json + Service Worker)。
- App Store / Google Play の審査を待たずに即リリース・即アップデートできる。
- カメラ(`<input capture>` / `getUserMedia`)、マイク(Web Speech API)は HTTPS 配信下(Vercel は標準でHTTPS)であれば安定して動作する。
- 将来的にネイティブアプリ化(React Native 等)する場合も、ビジネスロジック(AI連携・問題生成ロジック)をAPIルートに切り出しておけば流用しやすい。

## 5. 機能要件

### 5.1 共通基盤

- ペルソナ選択→イントロ→撮影→生成中→問題集確認→クイズ→結果、の画面遷移をプロトタイプ通りに実装。**[Phase 1 実装済み]**
- 戻るボタン(画面スタック管理)、フッタータブバー(ホーム/スキャン/結果)。**[Phase 1 実装済み]**
- レスポンシブ対応(スマホ主体だがPC表示でも崩れないこと)。**[Phase 1 実装済み]**

### 5.2 AI問題生成(最重要)**[Phase 1 実装済み]**

- 撮影した画像(複数枚可・最大4枚)を Claude API にVision入力として送信。
- プロンプトで「OCR→重要ポイント抽出→カテゴリ分類→設問生成(選択式/○×/穴埋め、各設問に解説文つき)」を1回のAPI呼び出しで行う。
- レスポンスは構造化JSON(tool use)でパースする。
- 今後: 同一教材の再生成を防ぐキャッシュ、プロンプトキャッシュの活用(約90%割引)、DB保存は未実装(Phase 2以降)。

### 5.3 復習スケジュール(間隔反復)**[Phase 1 実装済み]**

- 正答率80%以上→7日後、50%以上→3日後、それ未満→翌日、のロジックを実装済み(`ResultsScreen.tsx`)。
- 将来的にSM-2アルゴリズム等への高度化を見据えたテーブル設計にする(正答履歴を蓄積しておく)ことは未着手。

### 5.4 お子さま向け機能 **[Phase 3・未着手]**

プロトタイプ(2回目の共有分、`index_16.html` 相当)は以下の水準まで作り込み済み。本番実装はこの挙動をそのまま踏襲すること(仕様の後退がないように)。

- **さんすう(計算練習):** `generateArithmeticProblem()` と同じロジック(足し算1〜9、引き算2〜10の範囲)をクライアントサイドで実装。AI呼び出し不要。
- **音声読み上げ必須:** 出題のたびに「3 たす 4 は?」のように自然な日本語文でWeb Speech API(`SpeechSynthesisUtterance`, `lang='ja-JP'`)を使い自動読み上げる。正誤判定後も「せいかい!」「おしい!こたえは○」を読み上げる。画面右上に🔊/🔇の音声ON/OFFトグルを設置し、`speechEnabled` のようなグローバル状態でしりとり画面のトグルと状態を共有する。
- **AIしりとり(最重要):** 固定辞書1,760語(頭文字ごとに40語ずつ均等収録)+ 特別な「わざと負ける」用の「ん」終わり単語プール(24語)で構成。本番でも最低限この語彙規模・振る舞いを維持し、余力があればClaude APIによる動的生成に発展させる。
  - **わざとAIが負ける演出:** 子供が一方的に負け続けないよう、AIは時々「ん」で終わる単語(うどん、きりん、ほん 等)をわざと選んで自分から負ける。調整値: 「単語が20語連なるまでは発動なし→以降は経過語数に応じて確率が上がり(最大90%)→36語超で確定発動、42語で強制終了」。やり取りは平均24〜25語(体感10〜15往復)、8割以上が20〜30語の範囲に収まるようチューニングされている。本番でも同等のペース感を再現すること。
  - **濁点・半濁点の正規化が必須(実装時にハマりやすい落とし穴):** 収録した単語リストは「が」「ば」「ぱ」等の濁音・半濁音で始まる単語が0件のため、「が→か」「ば/ぱ→は」のように清音に正規化してから次の頭文字判定を行わないと、濁音で終わる単語(全体の約16%)が即詰みになる。`KANA_NORMALIZE` テーブルをそのまま移植すること。
  - 小さい「ゃゅょ」で終わる単語も、それぞれ「や/ゆ/よ」として正規化してから次の頭文字と照合する。
  - **Claude API連携に発展させる場合のフロー:** 子供の発話(音声認識テキスト or 手入力)→ サーバーで上記の正規化を含むルールをバリデーション → Claude APIに「今の言葉のチェーン」と「使用済み単語リスト」を渡し、次の単語(ひらがなの一般名詞、幼児にわかる言葉)を1つ返させる。わざと負ける演出もプロンプトで指示可能。
  - **安全対策:** 幼児向けなので、Claude APIの出力は不適切語を含まないよう厳格なシステムプロンプトで制約し、出力後にも簡易フィルタを通す。
  - **音声読み上げ必須:** AIが単語を言うたびに読み上げ、正誤フィードバック(「おしい!」「もうつかったよ」等)や決着時のセリフも読み上げる。ただし同時に複数の発話が重ならないよう、連続する発話には短いタイムラグ(0.8〜1.8秒程度)を入れる。
  - ひらがな以外(漢字/カタカナ)入力の正規化ロジック(`normalizeKana`, `KANJI_TO_HIRAGANA`)は流用可能。ただし語彙が1,760語に拡張されたため、旧194語分のkanji変換表のみでは網羅率が低い。将来的に主要単語ぶんの漢字表記も拡充するとよい。
  - マイク入力: Web Speech API(`lang='ja-JP'`)をそのまま使用。ブラウザ非対応時のフォールバック文言もプロトタイプ通り実装。

### 5.5 先生・企業ペルソナ向け **[Phase 2・次の着手対象]**

- **Phase 4:** 決済(Stripe)・サブスクリプションプラン・利用制限(無料枠/有料枠)。

## 7. 非機能要件

- **プライバシー:** 撮影画像は問題生成後に自動削除(特に企業ペルソナのマニュアル等)。現状はAPIに一時的に送信するのみでサーバー保存はしていない。
- **コスト管理:** Claude APIのトークン使用量をユーザー・プランごとに可視化・上限設定できるようにする(未実装)。
- **アクセシビリティ:** 文字サイズ・コントラストはプロトタイプのダークテーマを踏襲しつつ、WCAG AA相当のコントラスト比を確保する。
